# ZIKARON family components

Shared components of the three desktop apps of the family (ZIKARON, GALEED, ERAVON). Each component carries a family version number. A project that changes a component bumps its number at release; the others see the higher number, read the diff between the two releases of that project, and decide what to pull. The number records what was done, not bytes; it moves only at release.

This list is ZIKARON's, as of release 0.1.3. Paths are relative to this repository at that release. The machine-readable form is `family-components.json`; the literals a port must replace are in `crates/app/family-literals.json`.

## Changes in 0.1.3

- `transport` 3: the system's automatic configuration script (PAC) is run in an isolated QuickJS engine (standard PAC functions only, no network, files, modules or timers; time, memory and stack caps; name lookups answered outside), and the ways it names are tried in turn, `SOCKS` as SOCKS5 then SOCKS4a; a script is fetched only from this machine over `http` or from anywhere over `https`, redirects included (`PAC_REMOTE_HTTP` otherwise); automatic discovery (WPAD) is not done; proxies that ask for credentials (HTTP Basic, SOCKS5 user name and password) are answered, and a missing or refused credential is named apart from an unreachable proxy; HTTPS proxies (TLS to the proxy and to the node, each certificate checked) and SOCKS4/4a; under a custom proxy, private, link-local, loopback and `.local` nodes go straight; TLS reads and handshakes are driven one socket step at a time, so a peer that trickles bytes meets the deadline; why a connection went without its script is kept until a connection to that node is made, so a failure can say it; the custom proxy's cells are judged in one place (`proxycells`): a whole address is split into them on one paste or when the host cell is left, never mid-typing, and a saved password stays only with the very proxy it was given to (same kind, host, port and user name).
- `node-answer` 3: a proxy asking for credentials is its own sentence and code, given or not; a failure after the script was left unused carries the script's trouble as its next step; when every node fails, the first failure is kept whole with every node's words as its evidence.
- `log-scan` 3: a public paged reader of logs over a block window, its filter forms pinned (no address, an open topic, one topic, any of several).
- `tx-send` 3: gas estimates are judged as a quantity across nodes (the largest is taken); the queue holds exactly the entries not yet seen confirmed on chain (an entry the audit sees on chain leaves unless its transaction is out, one the chain lacks is queued again); the command line asks the registry before sending and does not send what is already there (`E_ON_CHAIN`); earlier data forms are not read.
- `node-agreement` 3: `eth_estimateGas` is judged by quantity, not by sameness; waiting for a receipt does not end early because one node lags.
- `os-platform` 3: Linux reads the desktop's proxy settings from disk (KDE `kioslaverc`; GNOME, Cinnamon and MATE GSettings from the dconf database or keyfile, no program started) before the environment; Windows reads the current connection's settings as browsers do, the machine's under the machine-wide policy, and every proxy-list spelling; automatic discovery is not read; the command line reads the terminal's proxy variables before the system; Windows time zones take each year's rule; the one memory wipe lives here, and every other crate forbids `unsafe`.
- `durable-write` 3: one temporary-name shape for every write, a write that does not land removes its temporary file, and the writer sweeps leftovers on opening; files are created owner-only; the machine settings are split into a plain file holding only what the passcode gate needs (language, appearance) and an encrypted part read after unlocking; earlier data forms are named and left as they are, never converted.
- `single-writer` 3: with the command line writing on its own, the desktop takes the writer lock for each write and releases it, rereading first if the command line wrote; a ledger handed off stops being written here until its handoff comes back, and only a handoff that follows on is taken (`handover`); the writer lock and its outcomes live in the sealed layer.
- `local-seal` 3: the envelope, its keys and names moved to the sealed layer (`zikaron-seal`) so the desktop and the command line seal and open through one implementation; only this version's forms are read.
- `passcode-gate` 3: a passcode checked in the background only checks it, and an action whose vault locked meanwhile is not done; the key store moved to the sealed layer; each secret of a mnemonic identity has its own recovery seal, so one can be recovered from its private key as well as from its words.
- `key-file` 3: an identity lands on the seat in use when it has one, else its first seat, by one rule for create, import, restore and switch; key derivation moved to the sealed layer; secrets are wiped by the platform layer's one wipe.
- `machine-backup` 3: a backup failing anywhere in its task is recorded and named; the backup takes the machine settings as read, the plain and the encrypted part together, and its index is sealed.
- `ui-kit` 4: the page table is the product's, handed to the kit (routes, history, sidebar, wizard steps); the first-run wizard's Back follows its pages; a passcode row takes keys only on the topmost layer; floating cards stay inside the pane they open from; `Show` is followed every frame; pages declare their own drop zones; toasts wait for the last to fade; full-window pages keep clear of the scroll bar; the sidebar's last sync shows the date across days; a toast's key and icon share one rule.
- `bilingual-table` 3: the language can be chosen at first start (kept on the machine) and no longer on the passcode gate; the English word for one record is "Entry".
- `app-skeleton` 3: new named refusals for the command-line credential, writing locks, adoption, handoffs and proxy credentials; a PAC failure is said as the next step of the connection failure it caused.
- `cli-skeleton` 3: `kit-verify`, `hand-over` and `take-over`; reading verbs open a home with the credential; `anchor` asks the chain first; the line refusing an entry's body names its flags in both languages; `--proxy system` reads the terminal's proxy variables first; an unreached endpoint names a proxy asking for credentials (`token`) and a configuration script left unused (stderr line).
- `cli-desktop` 3: two switches, writing through the desktop and writing alone with a time-limited credential the desktop issues; the command line writes a sealed home with it by the desktop's own implementation; a ledger adopted into the desktop is refused at its old folder (`E_ADOPTED`); `succeed` is done on the desktop only; the desktop's answer to a request follows its own task, not its kind.
- `ci-toolchain` 3: every build and test is a release build with integer overflow checked, the profile the shipped binaries use; `zikaron-seal` joins the workspace.
- `family-literals` 3: the one-file extensions (`zkit`, `zkhand`), the handoff note and the handed-ledgers list registered as contact names.
- `structure-pins` 3: pins follow the sealed layer, the write locks, the queue that follows the chain and the handoff rules.
- `sealed-layer` 1 and `one-file` 1: new.

## Changes in 0.1.2

- `transport` 2: a peer that does not speak TLS is named as the handshake layer; node sentences never repeat a key from the address; every socket read waits one 250 ms slice at most and then looks at the shutdown flag, so quitting cuts an exchange in flight on every system, and each cut is counted.
- `node-answer` 2: node errors and addresses are said without the key in the address, whatever its form (a node address is its own type, said only through its sayable form); every channel names its own place.
- `log-scan` 2: the code question and the fingerprint check wait out rate limits by the patience table; spans are remembered per place.
- `tx-send` 2: the command line's direct send asks by hash before signing again and records what it signed; the balance check is pinned to the lowest head and compared; a voided batch is named.
- `os-platform` 2: the home is read from the variable the system sets for it first (`HOME`, `USERPROFILE`), and the profile folder is recognised however it is spelled; kernel locks are listed and closed in a starting child; the desktop channel closes at once on every system and checks a client's user in a second step; on Windows a rename waits out a file another handle holds for at most a second, then refuses as the system did.
- `node-agreement` 2: a chain height in the wrong shape is refused by name, never read as zero; the balance is compared across nodes.
- `durable-write` 2: a failed whole-machine backup is recorded and named; a strict read names a zero-byte entry file; a backup lands under a numbered name in one step that never replaces a file.
- `single-writer` 2: a writer mark that does not read opens read-only and is left as it is; the banner says so; the writer lock is never inherited by a program the app starts.
- `local-seal` 2: the place digest in the envelope header is keyed (third envelope); older envelopes still read.
- `passcode-gate` 2: a passcode is moved out to the task that derives with it, leaving the action's cell empty, so no second copy stays in memory; one never handed over is zeroed when the action is dropped.
- `key-file` 2: a key file of the wrong shape or out of bounds is refused before any derivation runs; the backup cost floor is one constant, the level key files are written at.
- `machine-backup` 2: one transcription seam for every part of the package; a backup that does not read back is recorded as failed; a backup never replaces a file whose name it would take.
- `ui-kit` 3: a leaving layer skips the placeholder colour; toasts and key-value values wrap between English words; the identity lens menu is the account switcher again; recovery words on screen are held in the secret type and zeroed when hidden.
- `bilingual-table` 2: the first layer of the English interface carries no Chinese evidence words.
- `app-skeleton` 2: new named refusals (identity already here, name taken, record place on more than one line); a voided batch is said in both languages; an incomplete data-folder layout is judged once when it opens; an identity's network is one closed cell; a passcode is handed to its task, not copied.
- `cli-skeleton` 2: the direct `anchor` keeps a record of what it signed and answers a void as `E_TX_VOID`; `adopt` joins the verbs the desktop does.
- `packaging-release` 2: packaging scripts refuse binaries that carry a build-machine path; the root licence summary is generated.
- `ci-toolchain` 2: workflows on the Node 24 action majors; the Linux image is named; every test target runs without stopping at the first failure; the scrypt crates are optimised in debug builds.
- `family-literals` 2: contact paths registered; descriptions corrected; an empty `foreign` section.
- `structure-pins` 2: pins follow the third envelope, the writer mark rules and the numbered backup landing.
- `cli-desktop` 2: a voided batch through the desktop answers `E_TX_VOID`; the setting reads "Queue only"; `adopt` goes through the desktop and a co-signature with one half only is refused; after the app quits, the command line learns at once that it is not running.
